# personal_agent_system
## A8 个人数字分身代理系统：面向社交沟通的 AI Agent 设计 
## 赛题简介  
随着即时通讯软件（如 QQ、微信等）的广泛使用，用户每天需要处理大
量重复性沟通任务，这些沟通行为往往具有明显的个人表达习惯和固定
模式。因此可以构建一个数字分身代理系统，在用户授权的前提下，帮
助用户处理部分低风险沟通任务。本赛题要求参赛队伍设计并实现一个
可接入社交平台的数字分身 Agent 系统。系统在获得用户授权后，可以
读取消息并在一定范围内生成回复建议或自动回复。同时系统必须满足
用户隐私保护和对话隔离等安全性要求。 

赛题业务场景  ·重复信息回复：用户经常收到类似问题，如“资料在哪里？”、“什么时
候提交作业？”、“会议几点开始？”。数字分身可以进行检索用户资料库，
生成回复建议，在授权情况下自动回复。 
·用户不在线时的基础代理：当用户暂时不在线时，数字分身可以回复
简单问题，提供已授权资料以及说明用户状态。 
·风格一致的回复生成：系统通过学习用户历史表达方式，生成符合用
户习惯的语言风格。 
·不确定问题确认：当系统无法确认答案时，不再自动生成确定性回答
并通知用户确认。 
## 功能性需求  
### 1.社交平台接入模块：
系统需要支持接入至少一个聊天环境，例如：QQ
机器人接口、模拟聊天接或Web聊天环境。基本功能有接收消息、解析
消息、内容输出回复。 
### 2.权限与身份管理模块:
系统必须具备权限控制能力。不同联系人可能具
有不同权限：系统需要支持：联系人权限设置、自动回复开关、敏感操作
确认。 
### 3.指令配置与初始化模块：
系统应支持用户通过指令配置数字分身行为。
 
### 4.回复生成模块：
系统根据以下信息生成回复：当前消息内容、用户知识
库、用户表达风格、权限策略。回复方式分为自动回复和由用户确认的
回复。 
### 5安全与隐私保护模块：
系统必须具备基本对话隔离安全机制。不同聊天
对象之间的数据必须隔离：不得将 A 对话内容用于 B 对话，也不得泄
露历史聊天记录。 
非功能性需求  可解释性：系统生成回复时应能说明依据，例如：来自用户资料库、根据
历史回复模式生成等。 
其他限制条件  ·语言：不限。 
·允许调用第三方 AI 功能。 
加分项  
1.风格学习优化：系统能通过历史消息逐渐优化回复风格。 
2.多社交平台支持：接入多个社交媒体中。 
3.多文档联合问答：系统可以同时利用多个文档内容回答问题。 
4.多模态能力：支持识别语言、图片、视频等多模态信息。
